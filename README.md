## Overview

**AMAN-LLM** is a **defense-in-depth security architecture** for **tool-using LLM agents** that interact in **Algerian Arabic (Darja)**, **Arabizi**, **Modern Standard Arabic (MSA)**, **French**, and **English**.

LLM agents that call external tools (web search, databases, code execution) expand the attack surface from unsafe text to **prompt injection, unauthorized tool invocation, ungrounded outputs, and audit-integrity failures**. These risks are amplified for dialectal and non-standard Arabic, where existing safeguards are weakest.

Rather than relying on a single moderation filter, AMAN-LLM distributes complementary controls across the agent lifecycle:

- **Input Sanitizer** (non-blocking normalization and de-obfuscation)
- **Layer 1: Input-level ethical filtering** (rule-based Cultural Filter + fine-tuned MARBERT Intent Classifier + fine-tuned DziriBERT Adversarial Detector)
- **Layer 2: Tool-invocation governance** (schema validation, injection detection, declarative policy rules)
- **Layer 3: Runtime monitoring and output validation** (claim verification, grounding, freshness, relevance, toxicity, PII, domain guards)
- **Layer 4: Bounded constitutional self-critique** (critique → rewrite → verify)
- **Audit Logger** (hash-chained, trace-correlated, PII-redacting)
- **Pipeline Orchestrator** (shared distributed trace ID across all stages)

> **Scope note:** all results characterize robustness under the *evaluated* threat conditions on manually constructed, non-production benchmarks. They are not security guarantees for real-world deployments.

---

# Features

- Dialect- and script-aware input defense (Darja, Arabizi, Franco-Arabic, MSA, French, English)
- Independent mediation of **every** planned tool call (authorization is not inherited from Layer 1)
- Post-generation verification with fail-closed semantics
- Conditional, bounded constitutional self-assessment (Q1a–Q10 rule set)
- Hash-chained, tamper-evident audit logging with default PII redaction
- Externalized, versioned configuration for all thresholds and weights
- Per-layer threat model (assets, attacker capabilities, assumptions, attack surface)
- Layer-level ablation, isolation, and cross-layer replay experiments
- Dedicated Layer-1 component ablation and synthetic audit-integrity evaluation

---

# Architecture

```
User → Sanitizer → L1 → Agent Core ⇄ Tool Registry / L2 → L3 → L4 → Final Verified Response
```

with explicit short-circuit and fail-closed paths at every enforcement layer.

| Component | Role | Implementation |
|-----------|------|----------------|
| Input Sanitizer | Normalization, de-obfuscation, dialect evidence, risk level | Rule-based, non-blocking |
| Layer 1 – Cultural Filter (Agent 1) | Jurisdiction- and context-aware cultural-risk scoring | Rule-based |
| Layer 1 – Intent Classifier (Agent 2) | Four-class harm intent | Fine-tuned MARBERT |
| Layer 1 – Adversarial Detector (Agent 3) | Binary safe / adversarial | Fine-tuned DziriBERT |
| Agent Core | Reasoning, planning, tool selection | Aya Expanse 8B + LangGraph |
| Layer 2 | Schema → injection/encoding → policy gates (PR-01–PR-13) | Declarative YAML policies |
| Layer 3 | Claim, grounding, freshness, relevance, toxicity, PII, Islamic-content, financial checks | Embeddings + rules |
| Layer 4 | Constitutional critique / rewrite / verify | `qwen3.6-flash` via DashScope |
| Audit Logger | JSONL, SHA-256 hash chain, PII redaction, `fcntl` locking | `audit_logger.py` |

Tool Registry used in experiments: `DB_query`, `Websearch`, `Calculator`, `Python_executor`, `Vector_search` (the architecture itself is tool-agnostic).

# Key Findings

- **No single layer is sufficient.** Every stage used alone records an ASR above 70%, while the full pipeline reaches 2.93%.
- **Layer 1 matters most for attack resistance.** Removing it raises ASR from 2.93% to 50.80%, the largest increase of any ablation.
- **Layer 4 matters most for balanced performance.** Removing it causes the largest accuracy loss (−14.41 pp) and macro-F1 loss (−35.84 pp); it is also the only layer that can emit `rewrite`.
- **The Sanitizer has no standalone verdict but still helps.** Removing it costs more accuracy than removing Layer 2 or Layer 3; it recovers 143 of 231 otherwise-misclassified cases (61.9%), highest for French and lowest for MSA.
- **Layers 2 and 3 cover a narrow, otherwise-uncovered slice.** Under counterfactual replay, 97.7% and 92.8% of their catches are not independently intercepted by another layer.
- **Within Layer 1, the Cultural Filter and Intent Classifier are complementary.** Removing the Cultural Filter collapses recall on culturally coded harms (e.g. `state_institution_attack` 100% → 0%); removing the Intent Classifier collapses `hate_speech` recall (96% → 19%).
- **Security–latency trade-off.** Layer-4-routed cases have the highest mean end-to-end latency (5.13 s); whether selective routing could reduce this without losing quality is left open.
- **The `rewrite` decision is the least reliable surface:** 25 of 150 gold-rewrite cases did not receive the correct final outcome.
- **Hash chains have structural limits.** Trailing-entry deletion/truncation and coordinated forward rewrites require external append-only/WORM storage or keyed MACs to detect.

# Threat Model (Summary)

The attacker controls user input and may influence externally retrieved content, but **not** the trusted enforcement code, model parameters, policy rules, or protected credentials. Goals: bypass safety controls, induce unsafe tool invocation, exfiltrate sensitive data, manipulate outputs, or degrade availability. A per-layer table (assets, capabilities, assumptions, attack surface) is provided in the paper (Table 1).

| Layer | Primary defended threats |
|-------|--------------------------|
| L1 | Obfuscation, jailbreaks, prompt injection, culturally coded harm |
| L2 | SQLi, path traversal, SSRF, credential/PII leakage, privilege escalation, bulk exfiltration |
| L3 | Unsupported/fabricated claims, stale data, toxicity, PII, domain violations |
| L4 | Residual unsafe outputs (bounded, probabilistic safeguard) |

# Implementation Details

| Item | Setting |
|------|---------|
| Agent Core | Aya Expanse 8B (4-bit, greedy decoding, 256-token cap), LangGraph |
| Layer-1 encoders | MARBERT, DziriBERT; max length 64, batch 16, lr 2e-5, ≤ 4 epochs, early stopping (patience 2), weighted cross-entropy, seeds 42–44 |
| Layer 3 embeddings | `paraphrase-multilingual-MiniLM-L12-v2` (fallback: TF-IDF cosine, then Jaccard) |
| Layer 4 engine | `qwen3.6-flash` via Alibaba Cloud Model Studio (DashScope); temperatures 0.0 / 0.2 / 0.15 for critique / rewrite / verify |
| Key thresholds | θ_soft 0.30, θ_block 0.80, θ_sem = θ_rel 0.30, θ_tox 0.65, τ_evid 0.65, τ_contra 0.72, κ³_min 0.45, κ⁴_min 0.55 |
| Hardware | Google Colab (NVIDIA Tesla T4, 12 GB RAM); supplementary Kaggle (2× T4) |
| Software | Python 3.10, PyTorch 2.2, Transformers 4.40, LangGraph 0.1, scikit-learn 1.4 |

All thresholds and weights were specified **a priori** as configuration values and were **not** tuned on the evaluation benchmarks (paper Table 5).

# Dataset / Log Format

Each audit log entry is a structured JSON object:

| Field | Description |
|-------|-------------|
| event_id | Unique event identifier |
| timestamp | UTC timestamp |
| trace_id | UUID4 distributed trace ID shared across all stages for one query |
| stage | Pipeline stage that emitted the event |
| status | `PASS`, `BLOCK`, `ERROR`, `SOFT`, `ALLOW` |
| risk_level | `low`, `medium`, `high`, `critical` |
| details | Stage-specific payload (PII-redacted by default; `redacted: true` when triggered) |
| prev_hash / entry_hash | SHA-256 hash-chain links |

# Ethical Considerations

AMAN-LLM and its benchmarks contain adversarial content in Algerian Arabic and other languages, including hate speech, prompt-injection attempts, sensitive-data requests, and unsafe tool-use instructions, created for **defensive evaluation**.

The artifacts are released **exclusively for research purposes**, including

- LLM and agent safety
- Content moderation and guardrail research
- Secure and auditable agent design
- Benchmarking and robustness evaluation

They must **not** be used to facilitate malicious activity, to bypass deployed safety systems, or to generate harmful content. Deployers should additionally note that the Audit Logger's PII redaction is regex-driven and over-redacts some numeric identifiers, and that the system is a *mitigation* framework, not a guarantee.

# Limitations

- **Manually constructed benchmarks:** the 1,902-case and 682-case sets were not sampled from live traffic; results do not establish generalization to real-world distributions.
- **Annotation:** two annotators each labeled about half of the cases, with no full double annotation and no inter-annotator agreement statistic.
- **One-stage-at-a-time design:** ablation and isolation do not capture pairwise or higher-order layer interactions.
- **Heuristic baseline judge:** the unprotected Aya Expanse 8B baseline is scored with a pattern-based judge validated on only 30 cases; it assigns no `rewrite` outputs, which lowers its macro-F1.
- **Single backbone:** the Agent Core is Aya Expanse 8B only; domain-specific use cases (financial, Algerian legal, Islamic jurisprudence) are weakly evidenced.
- **Dialect coverage:** regional varieties (e.g. Wahrani, Chaoui), Amazigh varieties, registers, and speaker demographics are not systematically covered.
- **Non-adaptive attackers:** adaptive adversaries, multi-turn splitting, and indirect prompt injection are not evaluated.
- **Audit Logger:** evaluated on synthetic logs in a shared CPU sandbox; the hash chain does not detect T3/T5/T7 attacks, and keyed MAC/HMAC, external append-only storage, and remote attestation were not evaluated.
- **No third-party comparison:** no reproducible comparison against external guardrail or audit systems.
- **Layer-4 cost:** no selective-routing experiment was run, so the latency/quality trade-off is uncharacterized.
